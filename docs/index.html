데이터 제약 — 득점 전용

SofaScore의 KBO 데이터는 일정·이닝별 득점·순위·팀/구장/감독만 제공한다. 볼카운트·주자·투수/타자·라인업·박스스코어·선수 기록·문자중계는 404다. 이 커버리지가 P0/P1 범위를 결정한다.

단일 요청 라이브

GET /sport/baseball/events/live 한 번이 진행 중인 KBO 전 경기를 반환한다. 경기별 개별 폴링이 필요 없어 트래픽·배터리·차단 위험이 모두 낮다.

최우선 리스크 — 403

분석 환경에서 API가 403이었다(출처 IP 기반 추정). 실기기 접근은 미검증. Step 1(DS-001)이 코드 작성 전 관문이다 — 실패 시 보조 소스로 재설계.

구현 로드맵 (Step 1 → 8)

각 단계는 “구현 → 자동 테스트 → 실기기 확인”으로 끝낸다. 카드를 눌러 상세로 이동.

Step 1접근성·스키마 스파이크0.5일실기기 403 여부와 라이브 스키마를 코드 전에 확인Step 2프로젝트 부트스트랩0.5일Compose·Hilt·Retrofit 3·Room·Coil 3 뼈대와 CIStep 3네트워크·매핑 계층1.5일DTO·매퍼·함정 7개 테스트로 고정Step 4Room + Repository + 프리페치2일시즌 전체를 로컬 SSOT로, 오프라인 날짜 탐색Step 5경기 목록1.5일날짜 네비게이션 + 라이브 폴링 1요청Step 6경기 상세1.5일동적 라인스코어(연장) + 종료 확정Step 7순위·팀·즐겨찾기1.5일승-패-무 파생, 팀 상세, 즐겨찾기Step 8마감1.5일접근성·적응형·성능·R8 릴리스

지금 시작할 3가지

  1. DS-001 실기기에서 SofaScore API 호출 성공 확인. 계획 전체의 전제. 가장 먼저.
  2. DS-002 게임 데이 18:30 KST 경기에서 라이브 응답 3시간 기록. 스크립트를 미리 준비.
  3. DS-010 Compose 프로젝트 생성. DS-002 대기 중 병행.
